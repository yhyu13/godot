## Key Learnings

<!-- Project-specific conventions discovered during development. -->
- `openwolf init` has a stale copy-list bug: `copyHookScripts` copies a fixed 13-file list of hooks from `dist/src/hooks/` into `.wolf/hooks/`, but the shipped `pre-read.js`/`pre-write.js` import `../specs/spec-store.js` + `../specs/inject.js` and init never copies the `specs/` runtime. Result: a fresh init's SDD spec-context injection + TDD reminder throw MODULE_NOT_FOUND (caught → fail open, silent). Fix: copy `openwolf`'s `dist/hooks/specs/*.js` into `.wolf/specs/` (NOT `.wolf/hooks/specs/` — the import is `../specs/` from `.wolf/hooks/`). The `specs/` runtime is self-contained (only `node:*` + `./types.js`). This repo is fixed as of 2026-08-30.
- `doc_ai/` holds cross-module AI/design/process docs (GODOT_LLM_DSL_DESIGN.md, SOP_TDD_AI_TESTING.md, PLAN_LLM_DSL_IMPL.md); `docs/` is reserved for the 144 module teaching docs (INDEX.md + DOC_SPEC.md).
- A new scripting language plugs into Godot C++ via 3 routes: `ScriptLanguage` (ScriptServer), GDExtension native (`object_method_bind_ptrcall`), or declarative `.tscn`/`.tres` (`ResourceFormatLoaderText`). No VM is required by the `ScriptInstance` interface.
- Standalone fast TDD harness for pure C++: `gdsl/test.ps1` sources vcvars64.bat, compiles with `cl /utf-8 /EHsc /std:c++17`, links doctest single header, runs in seconds (no engine rebuild).
- GDExtension ABI has **no** `object_emit_signal` (grep `core/extension/gdextension_interface.json` → zero hits). Emitting a signal from raw GDExtension C requires `classdb_get_method_bind("Object","emit_signal", hash)` + `object_method_bind_call`, and that hash must be exact: `ClassDB::get_method_with_compatibility` (`class_db.cpp:1166-1198`) returns nullptr unless `MethodBind::get_hash()` matches, and that hash = `MethodInfo::get_compatibility_hash()` (`method_bind.cpp:35-45`). The hash is name-independent and purely structural, and can be **computed from source** (port `hash_murmur3_one_32`+`hash_fmix32` from `core/templates/hashfuncs.h:112-122,144-150` + `get_compatibility_hash` from `core/object/method_info.cpp:86-116`) instead of requiring an `extension_api.json` dump. **CRITICAL correction (2026-08-31, real-machine verified)**: `Object::emit_signal` **has a return value (Error)** — the hand-written `mi` in `object.cpp:1866` omits return_val, but `create_vararg_method_bind` derives return type INT + class_name "Error" from the C++ signature (`type_info.h:247-256` MAKE_ENUM_TYPE_INFO). Omitting return_val produces the wrong hash. Correct hash = **4047867050 (0xF1458CAA)**, verified against real-machine `--dump-extension-api`. The older value 2866548813 (0xAADC104D) was wrong (treated emit_signal as no-return).
- Godot 4.7 ABI has **no** `variant_new_string_name`/`variant_new_string` (only `variant_new_copy`/`variant_new_nil` + generic `variant_construct`). To build a typed Variant from a raw builtin value use `get_variant_from_type_constructor(GDExtensionVariantType)` → `GDExtensionVariantFromTypeConstructorFunc(void(*)(GDExtensionUninitializedVariantPtr, GDExtensionTypePtr))` (wraps `VariantTypeConstructor<T>::variant_from_type`, `variant_internal.h:1002-1007`). `GDExtensionVariantType::STRING_NAME` = 21 (matches `Variant::Type`, `variant.h:96-124`).
- Godot 4.7 ABI has **no** `string_name_destroy` (only `string_name_new_with_latin1_chars`/`_utf8_`). StringName is refcounted + intern-table (`string_name.cpp:111-129` unref frees when refcount→0). **`p_is_static` does NOT change buffer ownership** — `StringName(const char*, bool p_static)` always `_data->name = p_name` (copies via `String::operator=` → `append_latin1`, `ustring.h:688`); `p_static` only sets `static_count` (`string_name.cpp:232,245`) used for leak reporting at cleanup. For compile-time literals, create the StringName **once** and cache it — per-call static StringName creation would leak `static_count` unboundedly (`string_name.cpp:231-232` increments static_count per static creation).
- `GDExtensionPropertyInfo` must NOT carry a NULL `hint_string` (nor NULL name/class_name): `PropertyInfo(const GDExtensionPropertyInfo&)` (`core/object/property_info.h:163-170`) unconditionally dereferences all three via `*reinterpret_cast<...*>`. NULL `hint_string` → crash at method/property registration time. Use a zero-initialized `static uint8_t empty_string[8]` (empty String, COW-null-safe) as the placeholder.
- `sizeof(Variant)` = 24 bytes (single-precision/`real_t=float`) or 40 (double), per `variant.h:162`; GDExtension assumes single precision → 24-byte 8-aligned holder.
- To syntax-check generated GDExtension C without a full engine build: hand-write a stub `gdextension_interface.h` with the real type/field names from the json, then `cl /c` the generated `.c` against it.
- GDExtension ABI has **no** `object_get_instance` (only `object_set_instance`, grep `gdextension_interface.json` → zero `object_get_instance`). The engine supplies `self` to a registered method via `p_instance` = `Object::_get_extension_instance()` (`gdextension.cpp:106`, `object.h:525`). To retrieve a *different* object's C struct (e.g. a collision `target`), the ONLY path is the instance-binding API: `object_set_instance_binding`/`object_get_instance_binding` keyed by the library token (`object.cpp:2153,2167`). A NULL `free_callback` in `GDExtensionInstanceBindingCallbacks` is safe (memory then freed by the extension's `free_instance_func`), avoiding double-free.
- `GDExtensionClassMethodInfo` requires `arguments_info` and `arguments_metadata` arrays of size `argument_count` whenever `argument_count > 0` (`gdextension.cpp:211-213` dereferences both). For a single OBJECT argument: `GDExtensionPropertyInfo{ type=GDEXTENSION_VARIANT_TYPE_OBJECT(=24), name="target", class_name=<TargetType>, hint=0, hint_string=NULL, usage=0 }` + metadata `GDEXTENSION_METHOD_ARGUMENT_METADATA_NONE(=0)`.
- To extract an Object from a Variant (in `call_func`): `get_variant_to_type_constructor(GDEXTENSION_VARIANT_TYPE_OBJECT)` → `void(*)(GDExtensionUninitializedTypePtr r_dest, GDExtensionVariantPtr)` fills a `GDExtensionObjectPtr`. In `ptrcall_func`, an OBJECT argument arrives as `*(GDExtensionObjectPtr *)p_args[0]` (a pointer to the object pointer).

## Decision Log

<!-- Significant technical decisions with rationale. Why X was chosen over Y. -->
- D8 (SDD system choice, 2026-08-30): spec-driven dev runs on **OpenWolf SDD** (in-repo `.wolf/` scaffolding + `openwolf spec` CLI), not GitHub Spec Kit (`specify` CLI). Rationale: on the test-enforcement axis OpenWolf has running hooks (post-test observes failures, pre-read/pre-write inject TDD reminders, tasks-template has hard phase gates) vs Spec Kit's zero-runtime "tests are OPTIONAL" templates. Spec Kit was never initialized in this repo (nothing to remove); the global `specify` CLI is left installed by explicit user choice.
- D9 (SDD gate promotion, 2026-08-30): SOP §4.4 DoD promoted from doc to a hard gate, both ways — (a) the `/implement` command (all 4 agent dirs) now refuses to check a task box without pasted green `--test` output; (b) `.wolf/hooks/post-test.js` marks the active spec `blocked` when a test fails during the `implement` phase. Known limit: `openwolf spec next` itself does not refuse on `blocked` (would need patching the global binary, lost on `openwolf update`), so (b) is a durable marker and (a) is the enforcement.
- D10 (retro-spec granularity, 2026-08-30): the DSL compiler is spec'd one spec per component — 8 retro-specs (001-json … 008-codegen-logic) mapping each gdsl translation unit's seam to its existing test file, plus 1 forward spec (009-engine-integration = S6) at a falsifiable scene-load bar. `doc_ai/` left untouched as the design archive.
- D1: DSL compiler kernel lives in standalone `gdsl/` with its own doctest harness (seconds per red-green); engine module integration deferred to slice S6. Rationale: cycle-time (SOP §1.1) beats test-convention consistency for pure functions.
- D2: first slice is the logic parser (`.gdsl` → AST), not the declarative JSON→tscn layer. User chose parser-first over my "declarative tracer bullet" recommendation.
- D4 (S6.2a): effect ontology v1 = `set_field` (`ref.field = / += / -= literal`) + single-comparison guard (`ref.field <cmp> literal`), `ref` ∈ {self, bare}. Rules compile to methods via `classdb_register_extension_class_method` (call_func + ptrcall_func). `emit_signal` deferred to S6.2b, cross-participant `target` deferred to S6.2c (explicitly rejected, not silently ignored).
- D5 (S6.2b): `emit_signal` via `classdb_get_method_bind("Object","emit_signal",hash)` + `object_method_bind_call`. Hash **computed from source** (murmur3/fmix port in `gdsl/abihash.h`) = 2866548813, not hand-invented — pins the "name-independent structural hash" fact and removes the need for an `extension_api.json` dump. Variant marshalling via `get_variant_from_type_constructor(STRING_NAME)` (4.7 has no `variant_new_string_name`). Signal names cached as static StringNames (no `string_name_destroy` in ABI → per-call creation would leak).
- D6 (S6.2c): `target` type is an explicit clause `rule <Name> by <Owner> [target <Type>]:`. Rejected "default target = by type" (equals self, pointless) and "fixed Node" (loses type safety). `by` remains the rule owner (self); referencing `target.<field>` without a `target` clause is a typecheck error.
- D7 (S6.2c): cross-object C-struct retrieval uses instance binding (`object_set_instance_binding`/`object_get_instance_binding`, token-keyed), since the ABI has no `object_get_instance`. `free_callback` = NULL (memory owned by `free_instance_func`). Rule methods with a target register `argument_count=1` + OBJECT `arguments_info`.
- D11 (S6.3, 2026-08-31): emit_signal compat hash corrected to 4047867050 (0xF1458CAA) after real-machine `--dump-extension-api` revealed `emit_signal` returns Error (INT + class_name "Error"), invalidating the source-derived 2866548813 that treated it as no-return. The hash is still computed from source (now including has_return + return type + return class_name), not hand-invented.
- D12 (S6.3, 2026-08-31): `GDExtensionPropertyInfo.hint_string` must point to a zero-initialized `gdsl_empty_string[8]`, never NULL — `PropertyInfo(const GDExtensionPropertyInfo&)` dereferences it unconditionally.
